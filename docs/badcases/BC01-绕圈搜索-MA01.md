# BC01 · 绕圈搜索：自检规则导致打满步数上限、空手终止

- 日期：2026-10-08 ｜ 环境：qwen-plus + prompt v0.2（自检规则版）+ 双工具 + MAX_STEPS=6
- 触发题：MA01「对比上海子公司和总部在年假、病假、加班调休三方面的规定差异」
- 同款复现：S01（16k tokens 空答案）、AG02（8.9k tokens 空答案）

## 轨迹

```
step1: search "上海子公司 年假 规定"        ← ✅ 定向正确，拿到子公司侧
step2: search "云启科技 病假 规定"          ← ✅
step3: search "云启科技 加班调休 规定"      ← ✅ 三维度已覆盖
step4: search "职级与假期对照表"            ← ⚠️ 开始重复验证（总部侧数据 step1 已含部分）
step5: search "云启科技 病假管理办法 2026"  ← ❌ 重搜 step2 已覆盖内容
step6: search "云启科技 加班调休 管理办法 2026" ← ❌ 重搜 step3
→ MAX_STEPS_REACHED，finalAnswer = null，answer = ""（0/5 facts）
```

## 原因分析

1. v0.2 自检规则（覆盖性/冲突/完整性三查）让模型进入"永远可以再验证一次"的循环——
   **从 v0.1 的过懒（答不全但交代）翻转为过触发（追求完备 → 打满上限 → 颗粒无收）**
2. MAX_STEPS 触发后的策略缺陷：循环直接空手终止——**6 步检索到的证据全部浪费**，
   连"基于已有信息作答并说明局限"的降级输出都没有（比基线的 2/5 更差）
3. 基线对照：同一题基线 2/5（单次检索只覆盖子公司侧，但模型诚实说明"未提供总部信息"）

## 修复方案（D4-5 继续）

1. **强制总结终止**：MAX_STEPS 触发时，循环追加一条"基于以上检索结果直接回答问题，
   并说明信息局限"的无工具 ask——已检索的证据不应浪费（预期 MA01 从 0/5 修复到 ≥4/5）
2. **prompt 收紧自检**：加"最多检索 3 次；第 3 次检索后必须基于已有信息作答，
   并说明信息不足之处"——把重搜预算显式化
3. 复测：MA01/S01/AG02 三题 + 对照题（E01-E10）确认修复未引入新回退
4. 遗留观察：step4 的"职级与假期对照表"检索说明模型知道总部侧该查什么——
   分解能力没问题，缺的是收敛判断
