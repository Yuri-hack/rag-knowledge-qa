# Prompt & 工具描述迭代记录

> 记录规则：每次改动记【日期 + 改了什么 + 为什么 + 效果】。效果用可观察行为描述（调没调工具、query 长相、token 数、答对没有）。

## 2026-10-05 · D1 · v0.1（独立实验验证通过）

**system prompt v0.1**

> 你是云启科技的内部制度问答助手。回答制度问题前，必须先调用 search_knowledge 检索知识库，并以检索结果为准；知识库没有的内容要明确说明，不要编造。今天是 2026-10-05。

设计动机：
1. "必须先检索"——否则模型凭预训练记忆直接答，检索Agent退化成聊天
2. "以检索结果为准 / 不要编造"——压幻觉
3. **写入当前日期**——版本判别的依据（"现在迟到扣多少"要靠它从多版本里选现行版；这是语料实验的配套设计）

**search_knowledge description v0.1**

> 检索公司内部制度知识库，返回相关制度条款片段。query 必须是自包含的检索关键词（多轮对话时先消解指代）。可多次调用：结果与问题冲突、或不含所需信息时，应加限定词（如年份、适用主体、部门）后重试。

设计动机：
1. "自包含"→ embedding 检索质量（"那病假呢"这种 query 检索必挂，D6 多轮的关键）
2. "可多次调用 + 加限定词重试"→ 把"换问法重搜"变成模型的默认行为，这是 D4 自评重试的地基

**实测效果（独立 main，qwen-plus，模拟检索结果）**

- 首轮即调工具，query=`"P5 年假 天数"`——**自包含要求自然生效，无需额外改写模块**
- 最终答案正确：8 + 2 = 10 天，还主动校验了 15 天上限
- 两轮共 806 tokens（D3 成本指标量级参考）
- 附带观察：答案末尾主动提出"如需确认司龄计算可进一步检索"——多步意愿存在

**遗留 / 待观察**

- 工具内 topK 设 5（基线流水线是 10）：agent 循环要省上下文。D3 记录该差异，保证成本对比口径一致
  - **【2026-10-12 订正】**上句口径不实：全链路检索默认 `topRatio=0.5` 动态截断（向上取整），实际有效条数——工具 topK=5→**3** 条、基线 topK=10→**5** 条、A′ topK=30→**15** 条。四臂对比的真实口径是 **3 vs 5**，不是 5 vs 10
  - **【2026-10-12 二次订正】**修正时误设 `topRatio=1.0`——该参数语义（`computeTakeCount`）是 **r≥1 按绝对条数**，1.0 = 每次搜索只返回 **1** 条！R03 复合题 agent 失败即此所致（每次搜索只见单个 chunk，绿色通道文档从未进入视野；trace 证据：三次检索均"共 1 条"）。已改为 `topRatio=5.0`（绝对 5 条，与基线有效条数对齐），复验 agent 3/3。**教训：这个 API 的 1.0 不是"100%比例"而是"1条"，修口径前必须读截断函数的语义分支**
  - **【2026-10-12 终态 · 三次订正】**工具配置最终对齐基线 `(topK=10, topRatio=0.5)`——召回宽度、rerank 竞争池（10 选 5）、最终条数与基线完全同构；此前 `topRatio=5.0` 虽对齐了条数（5=5）但召回池只有 5，Milvus 第 6-10 名失去 rerank 救援机会。**同时移除 400 字符/条的内容截断**：512→400 仅省 6-10% token，却系统性砍 chunk 尾部"文字版"数字行（语料为对抗表格切块特意加在尾部），制造基线不存在的失败面；上下文控制的大杠杆是条数与搜索预算。终态复验（`tool-final-agent-*.json`）：R01-03 仍 3/3（10.8k/7.3k/15.5k tokens，与截断版相当），MA01 4/5 不回归。**agent 与基线的单次检索自此逐字节等价，架构对比的剩余变量只有循环本身**
- 未验证 parallel tool calls（一次返回多个 tool_call）——D2 用 AgentTrace 观察
- "今天日期"写死在 prompt 里，生产应动态注入——D7 记为改进项

## 2026-10-08 · D4 · v0.2（自检规则 + 双工具）

**system prompt v0.2（在 v0.1 基础上增加第 2 条自检规则与第 3 条工具配合）**

新增核心（v0.1 没有）：
1. **覆盖性自检**："结果是否覆盖问题中的全部限定词（主体/年份/部门）？只覆盖部分主体或完全未提及问题指定主体时，必须换限定词再次检索"
   ——动机：46 篇语料实验发现的 C01 沉默失败（问上海子公司、答总部规定），根因是模型不会主动比对"问题限定词 vs 结果覆盖面"。这条规则把隐式失败变成显式触发
2. **冲突处理规则**："数字不同时核对适用范围与年份，采用现行且匹配主体的条款，并在答案中明确指出冲突及采信依据"
   ——动机：B/C 区版本与范围变体的存在使冲突成为常态场景；实测 plus 能推理但 v0.1 没有强制"指出"的要求
3. **完整性自检**："多子问题逐一确认证据，缺失部分补充检索"
4. **get_document_detail 配合**："片段缺少数字/需确认适用范围时，按 documentId 拉全文"
   ——动机：C01 的分块切分使"数字 chunk 无身份"，重搜命中不可保证，拉全文是确定性修复

**新增工具 get_document_detail(documentId)**

**验证计划**：MA01（基线 2/5 facts）、S01（基线沉默答 8）为 Before 数字；三臂实验（A 基线 / A′ topK=30 / B 单次+同prompt / C agent）见 results/

**风险预告**：自评可能过触发（简单题多轮烧 token）——MAX_STEPS=6 + badcases 记录，校准是 D4 的核心工作

## 2026-10-12 · v0.3（对称分解 + 同义改写 + 预算 4）

**实测背景**：BC01 修复后复测——MA01 4/5（缺总部侧 1 项）、AG02 2/3（“审批时限”词汇鸿沟未召回）。
v0.2 的自检规则能发现问题但缺两把“检索工具”：

1. **对称分解（新规则 3）**：对比类问题必须按主体分别检索（每主体一条查询、覆盖全部维度），
   不得用混合查询——针对 MA01 step1 混合查询导致总部侧证据不全的问题
2. **同义改写（新规则 2d）**：问题概念在结果中无对应表述时换同义词/具体说法重搜
   （“审批时限”→“补录/审批/复核/办理时限”）——针对 AG02 的词汇鸿沟失败
3. **预算 3 → 4**：对称分解需要多一轮
4. AgentDemoRunner 旧 prompt（v0.1）同步为 v0.3（修复评估文档 P3 项）

**验证口径**：复测 MA01（预期 ≥4/5，目标 5/5）、AG02（预期 3/3）、MA02（4/4 防回退），
加对照题 E01/E10/S02 确认无新回退。对照题若有回落，说明预算放宽引入了新问题。

## 2026-10-12 · v0.3 预算实验（预算 6：检索全覆盖但生成被稀释）

**实验**：MA01 预算 4→6 + MAX_STEPS 8。
**轨迹（行为满分）**：step1 并行 3×子公司维度检索、step2 并行 3×总部维度检索、step3 并行 3×get_document_detail——
6/6 主体×维度组合全覆盖 + 3 份全文确认，对称分解完美执行。
**结果（质量下降）**：facts 4/5 → 3/5（总部侧 8 天、1:1.5 未进答案）；tokens 17k→22k。
**结论**：检索预算不是越大越好——6 轮证据 + 3 份全文把 context 推到稀释区，
生成端抓不住重点（lost-in-the-middle）。**预算 4 为当前最优**；预算-质量曲线呈倒 U。
**遗留**：MA01 的 5/5 需要"总部加班调休"维度的定向检索而非全文拉取——记录待 v0.4 或放弃（边际收益低）。
