## 结论

**1. AZ 区成立：agent 链路（B 与 C）对基线 A 是 5/5 vs 0/5 的完胜。** 基线败因全部是结构性的：
AZ01/AZ02 单次检索 5-chunk 上下文装不下多文档证据；AZ03 检索 miss 后无重试动作；
AZ04/05 无自检规则。与四臂终表（常规题四臂打平）合并后，路由边界更清晰：
**证据宽度超过单次检索上下文、或需要检索失败恢复/冲突审计的题 → agent 链路。**

**2. 但优势归因是 prompt（自检规则），不是循环。** B 用同 prompt 单次检索拿到与 C 相同的结果——
本轮正式题措辞下 qwen embedding 的混合查询召回比探针预期更强（AZ01 一条查询召回了
密码/调休 chunk）。C 的循环真正不可替代的动作（AZ03 换词重搜/拉全文）在 B 上以
"运气召回归一"的方式被抵消。C 相对 B 的净增益 ≈ 1.6k tokens 的成本，无正确率差。

**3. B 臂新发现的口径问题——虚构检索叙事**：B（单发）在 agent prompt 下会叙述
"后续两次检索未返回…"这类从未发生的检索动作（AZ03）。引用的文档证据是真实的（来自
唯一一次检索），但"检索过 X 次"的行为叙事是编造的。B 臂结果用于"答案正确性"可信，
用于"行为/过程分析"不可信——eval 报告中 B 臂答案文本需加此警示。

**4. judge 稳定性问题（对本轮可信度的影响最大）**：temp=0 下，对内容实质相同的答案
（AZ03 的 B vs C、AZ05 的 B vs C）给出不同 verdict；且系统性偏差——
奖励"听起来完整"的答案（A-AZ05 编造的提前期被 judge 采信为 CORRECT）、
惩罚诚实披露缺失（C-AZ04 因列出未覆盖项被判 PARTIAL）。
**跨臂对比的 judge 结论必须人工抽检**（本表第 6 列），或改用 pairwise judge（两臂答案同题对判）。

## 修订建议（未执行，待确认）

- judge prompt v3：加入"诚实披露知识库未覆盖 = 不扣分"与"无依据的实务建议 = 编造"两条判据，

  需要用更口语化/间接的措辞（AZ03 的"电脑坏了维修店"模式）而非主题罗列式。
