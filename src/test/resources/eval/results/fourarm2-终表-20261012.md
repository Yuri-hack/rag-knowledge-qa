## 裁决性结论（相对首轮四臂的变化）

**1. 正确率维度四臂实质打平（28-29/29）**——首轮"C 22/25 落后"的表象由两部分构成：
infra 污染（E01 一次 IOException，已由口径修复消除，本轮 infra=0）与工具配置未对齐
（topK=5→实得 3 条，已由 tool-final 配置消除）。用户先验"agent 不应不如基线"得到数据确认。

**2. agent 的正确率优势归零，成本劣势仍在**：C 与 A′ 并列 29/29，但 C 的 token 是 A 的 4.5 倍、
延迟 2.4 倍。首轮"S01 唯一被 agent 修复"在语料 v1.1 后已退役（本轮四臂 S01 全 CORRECT）。

**3. 范围外拒答（W01）仍是 prompt 贡献而非循环贡献**：B（同 prompt 单次检索）与 C 同为 CORRECT，
A/A′ 越权作答 WRONG。归属与首轮一致。

**4. A′ 大 K 本轮不再掉分**（29/29，首轮 MA01 曾 0/5）：语料 v1.1 的 scope anchors 显著降低了
大召回的噪声稀释。但 2.4 倍 token 成本仍无对应收益，"调大 K"依旧不划算。

**5. 工程决策维持"按题路由"且更明确**：
```
正确率敏感、成本敏感的简单/常规题 → 基线（topK=10，2.0k tokens，9s，29/29）
需要诚实拒答/可审计轨迹/多轮/未来工具扩展 → agent（结构性能力，正确率不输但 4.5x 成本）
多轮指代（MT01-07）→ 基线+D6 记忆（2/7 vs 7/7 已验收；agent 记忆 = D7 待办）
```
