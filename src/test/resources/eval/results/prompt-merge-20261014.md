# 行为规则合并实验：prompt 变体对照（2026-10-14，深池 N=20/K=10，20+5 题）

> 目的：验证"把 agent 提示词（v0.4）的行为规则合入基线 prompt，能否以基线成本拿到 B 臂（singleshot）的质量"。
> 方法：同一份代码、同一套配置，**唯一变量是 prompt 文本**（用 `spring.config.additional-location` 注入变体，互不污染）；
> 每次运行的 `promptVersion`（prompt 文本 sha256 前 8 位）落进结果 JSON，可事后核对（BC02 教训的工程化）。
> 题集：20 题子集（10 单跳 E01-E10 + 10 多事实 MA/AG/AZ）+ 5 道行为题（AZ03/AZ04/AZ05/S01/W01）。

## 一、prompt 变体对照（20 题子集）

| 变体 | 说明 | 通过 | 单跳 | 多事实 | avgTokens | avgTTFT | promptVersion |
|---|---|---|---|---|---|---|---|
| v1（旧 prompt） | 现状基线 prompt | 16/20 | 10/10 | 6/10 | 2,961 | 1.33s | `rag-9b83f567` |
| v2（规则改写） | 我重写：4 条行为规则 + 简洁约束 + 删除有害规则 | 16/20 | 10/10 | 6/10 | 3,133 | 1.21s | `rag-32c87018` |
| v3（v0.4 逐字去工具） | 把 agent prompt v0.4 逐字移植，仅删工具条目 | 15/20 | 10/10 | 5/10 | 3,162 | 1.34s | `rag-845e1156` |
| v4（v1 + 证据放 user 轮） | 格式与 B 臂同构（【检索结果】注入 user 消息） | 15/20 | 10/10 | 5/10 | 3,064 | — | `rag-9b83f567` |
| **B 臂（参照）** | agent prompt v0.4 全文 + 单次检索 | **18/20** | 10/10 | **8/10** | **14,876** | **18.0s** | `v0.4` |

**逐题差异只出现在 3 道题上**：AZ02（B 臂 3/3，其余 2/3）、AZ07（B 臂 6/6，其余 5/6）、MA01（v3 掉到 4/5，其余 5/5）。
其余 17 题五种变体完全一致。

## 二、行为题对照（v1 vs v2，judge + 人工）

| 题 | v1 judge | v2 judge | promptVersion 核对 |
|---|---|---|---|
| AZ03 / AZ04 / AZ05 / S01 / W01 | 5/5 CORRECT | 5/5 CORRECT | v1=`rag-9b83f567`，v2=`rag-32c87018` ✓ |

**judge 未测出差异**（该 judge 对"诚实边界"类差异不敏感，与会话早期的判断一致）。人工核对 AZ05 发现细微差别：

- **v1**：“未明确规定” → 但给出“**建议至少提前 5–7 个工作日提交申请**”（隐含为申报要求）；
- **v2**：“**知识库中未找到**关于提前天数的具体规定” → 补充“建议预留 **3 个工作日**完成审批流程”（明确区分流程时效与政策要求）。

结论：v2 的诚实边界更清楚，但差异**小且当前指标不可测**。

## 三、核心结论

**1. prompt 文本无法复现 B 臂的 +2 分。** 三个方向的尝试全部失败：
   - 自己重写规则（v2）：16/20，与 v1 逐题完全相同；
   - v0.4 逐字移植（v3）：15/20，反而略差；
   - 证据注入位置改为 user 轮（v4）：15/20，无增益。

**2. B 臂的增益与"推演 token 量"绑定**：B 臂 14,876 tokens（5 倍）、18s TTFT（15 倍），增益集中在
   多主体/多子问题题（AZ02 三件事、AZ07 六子问题）——这类题需要穷尽式核对，而穷尽核对本身要花 token。

**3. 因此"把规则合进基线 = 免费拿到 B 臂质量"这个假设不成立**：规则文本可以免费移植，
   但它并不驱动模型做那 5 倍的核对工作。

**4. 决策建议（按题型的路由，而非 prompt 合并）**：

| 题型 | 路径 | 依据 |
|---|---|---|
| 单事实题（E/V/S 类） | 基线（~3k token，1.2s） | 五种变体均 10/10，深池也已覆盖 |
| 多主体对比/聚合（MA/AG/AZ 类） | 预留冗长路径（B 臂或 agent，~15k token，18s） | B 臂 8/10 vs 基线 6/10 |

## 四、保留的工程改动

| 改动 | 价值 |
|---|---|
| 基线链路记录 `promptVersion`（prompt 文本哈希） | 每次结果都能对回确切的 prompt，prompt 漂移在数据里可见；本次实验靠它才发现"v1 覆盖未生效" |
| `rag.context-in-user-turn` 开关（默认 false） | 证据注入位置可配置，后续实验无需改代码 |
| RAG prompt v2 进默认配置 | 删除了有害规则（“不使用不确定词汇”），诚实/冲突规则更明确；**但按数据不应宣称为质量提升** |
| 语料清理 | 移除盲指针实验残留（G 区 10 篇，事实与正典重复），恢复 100 篇 / 258 chunks |
